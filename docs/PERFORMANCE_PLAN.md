# 50MB 文件与批处理验收方案

版本：0.2；状态：待执行，没有实际性能结果。

## 已知事实与基线

用户最大单文件约 50MB；后缀、公式数量、批次数、Windows 版本和硬件尚未确认。压缩体积不能代表公式规模或展开内存。建议测试基线 Windows 11 x64、16GB RAM、SSD；这是待确认的验收环境，不是最低配置承诺。

先盘点文件格式。基础读取器只处理 .xlsx/.xlsm；若实际样本为 .xls/.xlsb，先完成适配器评估，不能以改后缀或跳过样本代替验收。真实文件只在用户电脑测试。

## 样本矩阵

| 样本 | 检查重点 |
| --- | --- |
| 合成小型金标准 | 公式数、共享公式展开、引用与脱敏结果精确核对 |
| 合成公式密集文件 | 解析吞吐、模板归并、例外不丢失 |
| 合成共享字符串/样式密集文件 | 元数据流式索引和有界缓存 |
| 图片多、格式区域膨胀文件 | 不因体积或 dimensions 无条件遍历空单元格 |
| 整列引用、循环和跨文件文件组 | 区域节点紧凑存储、查询有界、断点显式报告 |
| 用户约 50MB 实际文件 | 本地完整流程的耗时、内存和兼容覆盖 |
| 连续 10 文件合成批次 | 资源释放、数据库写入、取消恢复和输入变化 |

## 测量方式

Release 构建、单读取任务起步；记录构建版本、OS、CPU、内存、磁盘类型、文件大小、实际记录数和公式数。真实路径及文件指纹只留本地，在线记录只能使用经检查的匿名统计。

同一样本至少运行三次，区分首次进程启动和后续运行，不冒称已清空 OS 文件缓存。记录各次读取、解析、索引、脱敏、导出耗时及总耗时，报告中位数和范围。记录进程峰值私有字节、峰值工作集、数据库/临时文件大小以及支持/不支持项计数。

对真实样本，读取公式数量与独立本地 OOXML 计数核对，共享公式按实例计数；抽查共享公式、跨文件和命名区域。计数相同只证明数量对齐，不能证明每条依赖正确；精确正确性另由金标准样本验证。

## 初始预算与判定

- 峰值私有内存 2GB 为初始软预算，尚未验证；超出必须定位，不默默截断数据。
- UI 每页建议 200 条，局部图默认最多 200 节点；分页与 UI 虚拟化同时实现。
- 进度更新建议每 250–500ms 一次；取消反馈目标 1 秒内，工作线程停止目标 5 秒内。不可中断 I/O 需显示正在收尾并记录超时。
- 耗时阈值在第一轮实测后冻结；不承诺 50MB 固定几秒或几分钟处理完。
- 中止任务释放文件句柄，保留已完成文件检查点；导出失败不得留下可误分享的正式包。
- 支持范围内合成金标准不得漏公式或错引用，未支持项必须计数；性能达标不能抵消隐私或正确性失败。

## 优化次序

按阶段计时定位瓶颈，再处理共享字符串/样式缓存、事务批大小、模板索引、局部查询。队列采用有界 Channel 并限制字符预算；SQLite 单写入通道。确认内存余量后才比较并发 1 与 2，不默认按 CPU 核数打开工作簿。不重算工作簿，不展开整列节点，不在 UI 中加载全项目。

流式读取依据：[微软 OpenXmlReader 大文件说明](https://learn.microsoft.com/en-us/office/open-xml/spreadsheet/how-to-parse-and-read-a-large-spreadsheet)。
