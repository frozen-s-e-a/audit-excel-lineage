# 审计 Excel 公式溯源与本地脱敏：可行实施方案

> 0.4 范围调整（2026-09-10）：当前基础程序以 [数值处理规则](PRIVACY_SPEC.md) 和 [运行说明](QUICK_START.md) 为准。以下 0.3 完整溯源设计保留供后续开发，不是当前程序的功能承诺；公式参数化、SQLite、CLI、安全 JSON 包暂未实现。

版本：0.3 · 更新日期：2026-09-10 · 状态：待实现设计

本版根据讨论，将主技术栈改为 C# / .NET 10 LTS + WPF，新增约 50MB 单文件的本地验收设计。50MB 是用户已提供的文件体积，不是已验证的性能指标，也不是支持上限。已提供 `.xlsx` 结构参考；整批格式分布、批次规模及目标电脑配置仍待确认，示例与最大文件的对应关系不作假定，当前不据此承诺全格式兼容或固定处理耗时。

## 1. 目标与成功条件

从一批相关的审计 Excel 文件中提取“哪些输入经过什么计算得到哪些输出”，为估值表、TT 表、附注表等实际存在的引用关系提供可追溯说明。对外分析只使用经本地检查的公式结构、匿名位置与必要业务语义。

用户需要得到三个结果：

1. 本地可浏览的公式清单与依赖图，可从目标单元格追到输入或已知断点。
2. 可交给外部模型的脱敏逻辑包，模型返回的解释可以按匿名编号映射回原位置。
3. 一份覆盖情况报告，明确公式提取、引用解析、语义标注和脱敏检查各自完成了多少。

完成共享公式、数组/溢出结果区域归属检查后，没有计算归属的值单元格才记录为“值输入，来源未证实”；不能仅因当前单元格没有 `<f>` 就认定为输入。不得仅因金额相等就把人工粘贴认定为引用，也不以提取出的公式直接代替审计结论。

| 命名区域 | 支持直接指向静态单元格/区域的名称，区分工作簿/工作表作用域 | 公式型名称、递归名称、动态名称 |

“保留函数调用”只表示结构识别；不保证公式数值结果、函数版本兼容或业务规则正确。查询函数的输入区域是潜在依赖，实际命中行依赖真实数据，必须区分两者。

## 3. 技术选择

| 层 | 选择 | 理由与约束 |
| --- | --- | --- |
| 核心引擎 | C# / .NET 10 LTS，首个交付目标 win-x64 | 统一文件扫描、解析、脱敏和导出；核心与界面解耦 |
| 常见 Excel 读取 | DocumentFormat.OpenXml（Open XML SDK）+ OpenXmlReader | 对 `.xlsx/.xlsm` 逐项读取公式和必要元数据，不默认加载整张工作表 DOM |
| 特殊格式 | IWorkbookReader 适配器 | `.xls/.xlsb` 的引擎按样本覆盖与许可评估后确定，统一输出私有记录 |
| ZIP/XML 处理 | System.IO.Compression + 受限 XML 读取 | 限制实际解压量、成员数和解析时间；额外 XML 读取禁止 DTD 与外部解析；审核所用 SDK 的解析配置 |
| 公式解析 | C# 分词器 + 有边界的表达式与引用解析器 | 第一版采用明确语法子集；SDK 读取公式文本不等于完成语法和依赖解析 |
| 本地状态 | Microsoft.Data.Sqlite | 保存匿名编号、公式索引、任务进度和标注；使用分批事务与单写入队列 |
| 界面 | WPF + MVVM；CommunityToolkit.Mvvm | 文件选择、分页表格、进度、取消、复核和局部依赖图 |
| 图显示 | WPF 绘图与受限树视图 | 按选中节点展开，限制节点数量；无远程前端资源 |
| 对外契约 | System.Text.Json + JSON Schema；后续扩展 JSONL 分片 | 使用安全 DTO 和字段白名单；大包增量写出 |
| 检查 | xUnit + JsonSchema.Net + .NET 分析器 | 验证引用、泄漏边界、格式契约与异常路径；不依赖在线校验 |
| 版本锁定 | global.json + Directory.Packages.props + packages.lock.json | 首轮 Windows 验证后锁定 SDK 和 NuGet 依赖；CI 使用 locked restore |
| Windows 交付 | dotnet publish，自包含目录发布 | 首先交付含 exe 的完整目录，在干净 Windows 测试；单文件发布后续评估 |

.NET 10 是当前 LTS 版本；WPF 面向 Windows。首个验收环境建议 Windows 11 x64，不能由此声称覆盖所有旧 Windows。公司实际系统、CPU 架构和部署限制在 P01 确认；自包含部署解决运行时分发，不改变操作系统支持范围。[.NET 下载与 LTS 信息](https://dotnet.microsoft.com/en-us/download/)、[WPF 文档](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/)、[.NET 部署说明](https://learn.microsoft.com/en-us/dotnet/core/deploying/)

微软提供 OpenXmlReader 的流式读取方法，可逐项读取 XML，降低加载完整 DOM 的内存压力；共享字符串、样式、索引和应用对象仍须独立控制内存。流式读取不是“峰值内存固定”或“C# 必然更快”的保证。[大文件读取说明](https://learn.microsoft.com/en-us/office/open-xml/spreadsheet/how-to-parse-and-read-a-large-spreadsheet)

JsonSchema.Net 支持 Draft 2020-12，数据契约继续使用已有 0.1.0 版本；语言变更不自动改变对外字段。[JsonSchema.Net 说明](https://docs.json-everything.net/schema/basics/)

读取器、隐私处理器和导出器使用不同的记录类型。导出器的函数参数只接受通过检查的安全类型；不得接收原工作簿、任意字典或原始路径，也不得把私有对象整体序列化后再删除几个字段。

Core 不引用 WPF、Open XML SDK 或 SQLite；Application 依赖 Core 的接口。读取、存储适配器实现这些接口，由 CLI/Desktop 的启动入口装配。数据流为私有读取记录、私有语法/依赖模型、安全 DTO、导出文件。所有格式适配器必须经过同一条脱敏路径，不得提供直接导出原数据的旁路。

SQLite 放在用户选择的独立本地项目目录，默认建议 `%LOCALAPPDATA%\AuditExcelLineage\projects\<项目ID>`；原数据目录和项目目录均位于代码仓库之外。SQLite 本身不提供这里所需的自动加密保证；本地访问控制沿用用户系统权限，若项目明确要求静态加密，应单列实现，不声称已经具备。

## 5. 批量处理算法

### 5.1 建立批次快照

- 递归扫描，跳过 `~$` 临时文件；输出目录不能作为新输入再次处理。
- 建立文件清单并分配项目内稳定代号；真实路径和完整文件指纹仅本地保存。
- 工作表别名必须与文件代号一起标识。不同文件中的 `Sheet1` 不是同一张表。
- 扫描期间文件变化则标记需要重扫，不混用两个版本的数据。
- 相同内容的多份文件不自动合并为同一业务文件。移动或改名通过本地重绑定流程保留编号；内容指纹只能作为候选证据。

### 5.2 静态提取

使用只读方式打开 SpreadsheetDocument，通过 OpenXmlReader 逐项读取工作表；公式读取 `<f>` 的文本和属性，保留共享公式编号及范围。读取外部关系时仅访问 ZIP 内成员及用户已指定的本地文件，不发起网络请求。通过 using/Dispose 释放文件资源，文件级检查点与事务保证失败不污染已完成文件。

通过工作簿关系定位实际 worksheet part，不假设 `sheetId` 等于 `sheetN.xml` 文件编号。共享公式按基公式相对偏移展开；数组/溢出分别检测并按支持矩阵处理，不把缓存值当公式。对外不得携带 `<v>` 计算结果、sharedStrings 原文全集或 externalLink 缓存。[公式与缓存的区别](https://learn.microsoft.com/en-us/office/open-xml/spreadsheet/working-with-formulas)

流式读取 sharedStrings，将需要的字符串索引放入本地索引或有界缓存；禁止为查询一个表头而默认加载完整 SharedStringTable DOM。样式和合并区域也受资源预算约束。允许按项目需要分批持久化真实数值、原始公式、缓存、文本及名称映射到仓库外的本地项目目录，用于复核和追溯；记录源文件版本和缓存未验证状态。持久化不等于允许对外导出，普通日志不倾倒这些原始内容。

源文件内隐藏表参与本地引用追踪，但隐藏内容并不自动获得导出资格。尺寸信息错误或仅有格式撑大区域时，以实际记录流为依据并报告异常，避免无条件遍历整张工作表。

### 5.2.1 分类与布局边界

按内容来源、存储值类型和业务含义分别建模，不将公式与数值作为互斥类型。普通值、公式结果缓存、共享字符串索引和空值分别处理；日期结合格式和日期系统解释。先恢复计算归属，再提取业务区域；表名、固定标题行和固定列不作为通用解析器的前提。详见 [分类与布局适配](EXCEL_CLASSIFICATION.md)。

### 5.3 解析与建立依赖

先实现 C# 分词器，再用明确优先级的表达式解析器处理括号、函数参数和引用；不能用一个正则匹配所有 `A1` 样式字符串。解析器输出带来源位置的语法节点，不执行公式。对于不支持的 token、函数或语法，记录结构化状态，原公式只留本地。必须用共享公式、带引号的表名、混合绝对引用和嵌套条件等金标准样本验证此部分，不能把 SDK 名称当作完整支持的依据。

引用记录需要保留：文件、表、地址、区域边界、行列是否绝对引用、名称作用域、引用角色和解析状态。名称可以含敏感信息，跨文件路径也可能藏在关系 XML 中，必须统一映射。

依赖方向统一为“输入 → 计算结果”。普通区域按区域节点存储；仅在局部查询时查出与区域相交的公式节点。所有公式分析都支持循环检测，不能假设整图一定无环。`calcChain` 不能替代从公式建立的依赖图。

SUMIFS、VLOOKUP 等查询或条件函数记录参与计算的潜在输入范围，不导出实际匹配行、匹配数量或真实分支结果。动态函数即使其参数引用已识别，目标范围仍可能是未知。

### 5.4 识别业务语义

读取合并表头、多层列标题、左侧行标题及必要单位提示，生成候选标签。用户可把候选值改为通用字段，如“市值”“成本”“净值”。审计表内任意文本均不能默认视为安全标题。

每个标签保留本地证据和确认状态。对外仅输出通用词典命中的标签或用户明确确认的概括标签；未确认时使用“字段_001”等代号。数字格式中的自定义文本不能原样带出，只抽象为金额、数量、比例等类型。

### 5.5 脱敏、归并和导出

脱敏细节见 [脱敏规范](PRIVACY_SPEC.md)。全批次统一别名；保留操作符、参数顺序和引用结构；业务常量使用不含真实值的参数。未知字符串和常量默认待复核。

公式归并使用“目标单元格相对偏移 + 绝对引用标志 + 归一化表达式树”，而不是删除行号后比较。相邻单元格错行、错列、异常固定引用、硬编码变化必须成为例外项。归并不是删除原始匿名位置映射；同模板也不代表业务正确。

导出只面向用户选定输出的依赖闭包，或用户选择的完整项目范围。完整明细地址和节点数量可能透露规模；高敏项目可选择仅输出模板级说明，并明确降低逐单元格追溯能力。

生成文件先进入临时目录，按契约校验和本地敏感内容检测，再进行预览确认和原子重命名。取消或失败不产生标为可分享的正式包。缺少引用来源时可导出明确标注 incomplete 的局部结果；不能标记 complete。

无法可靠脱敏的公式不得复制到包中：默认阻止导出；用户若选择仅导出已通过检查的子集，被省略项用匿名节点及错误代码表示，依赖断点和覆盖率必须随包给出。

## 6. 50MB 文件与批量性能设计

已知最大的实际文件约 50MB。文件体积不能直接推出已存在单元格数、公式数或峰值内存；图片、压缩率、共享字符串与样式数量都会影响测量。`.xls/.xlsb` 也不能套用 XML 工作表读取假设。

- 默认同时读取 1 个工作簿。完成基准后才评估 2 个及以上工作任务，不根据 CPU 核数自动全并发打开文件。
- 流式读取配合有界 Channel，限制记录队列和字符总量；逐批写入 SQLite，保留单写入通道、背压和取消传播。
- 不调用 `.ToList()` 收集全表，不为每个单元格创建界面 ViewModel；共享字符串、样式和本地语法树缓存也有预算。
- 整行整列使用区域索引，重复公式使用模板与实例位置；错行、固定引用或业务常量差异仍是独立例外。
- WPF 表格通过数据库分页查询并启用 UI 虚拟化。二者同时需要，UI 虚拟化不代表数据已经分页。图按邻域展开，默认最多 200 节点。
- 单 JSON 也采用增量写出，不先将全部节点序列化为一个大字符串。更大导出使用有版本和索引的 JSONL 分片；该扩展须先完善对应契约。
- CancellationToken 贯穿文件读取、队列、索引和导出；取消后保留已完成文件检查点，不留下可误分享的半成品。
- 日志只记录匿名编号、计数、阶段耗时和错误代码。真实样本、路径、文件指纹和字段值不进入仓库或云端 CI。

建议初始验收环境为 Windows 11 x64、16GB 内存、SSD；这是测试基线，不是用户已确认的电脑配置。初始峰值私有内存软预算设为 2GB，超过时记录和定位占用来源，不宣称已达标。总耗时先按读取、解析、索引、脱敏和导出分段实测，再冻结验收阈值；移除旧版基于未知样本的“5 分钟内”推定。完整用例、计量与本地样本流程见 [性能验收方案](PERFORMANCE_PLAN.md)。

## 7. Windows 使用流程

1. 创建本地项目并选输入文件夹。
2. 查看文件清单、格式支持、发现的外部依赖及来源缺失。
3. 执行分析，展示进度、可取消状态和错误项。
4. 浏览公式表；选择单元格查看直接输入、递归来源和使用它的结果。
5. 复核字段含义和常量分类，按规则批量确认可公开信息。
6. 预览实际对外包，看到保留内容、参数化内容和缺失项。
7. 导出；由用户将脱敏包提交到其选定模型。

第一版不内置模型 SDK，不自动联网。图视图、字体和资源均随程序打包。模型返回文本仅作为说明展示，不自动执行其中代码或修改原文件。

## 9. 开发节奏与交付边界

建议按 [开发任务](ROADMAP.md) 顺序推进：先确认格式并完成 C# 流式读取与语法子集的验证，再交付 CLI 闭环，最后接 WPF 界面和自包含发布。首轮本地样本盘点后再估工期；`.xls/.xlsb`、复杂公式及大共享字符串的支持工作不能由 50MB 文件体积单独估算。当前没有已完成的应用迁移，只有设计路线更新。

此轮交付是可供后续开发使用的方案、规范、数据契约及示例；不包含已实现应用、已验证的业务准确率或已构建的 exe。
