# 本地脱敏与导出规范

版本：0.2 · 本规范描述待实现行为。

## 1. 威胁模型与边界

外部模型只能收到用户选择导出的逻辑包。输入 Excel、真实业务值、真实名称、内部路径、完整文件指纹、映射数据库、详细异常、查询代码、宏和缓存默认不进入该包。

去标识化并不保证绝对匿名：行业字段、投资类别、业务结构、范围尺寸和公式本身也可能敏感。每个项目应有允许公开的语义范围；严格模式只输出确认过的必要信息。

## 2. 项目级代号

- 为文件、工作表、实体、账户和参数分别分配不带业务含义的代号。
- 代号在同一项目整批文件内一致，在无关项目间不共用映射。
- 映射保存在仓库之外的本地项目目录；不能用不加盐的名称/身份证/账号哈希替代此映射并对外公开。
- 身份编号规范化规则显式配置。不能对账户、证券代码等随意去前导零或忽略大小写。
- 同一敏感实体在值、字符串常量、标签和命名区域中使用同一代号；文件路径另按文件关系解析。
- 数字参数不应仅凭“数值相等”判定为同一业务参数。依据来源单元格、既有定义或用户确认建立一致关系。

## 3. 字段处理规则

| 类别 | 严格模式 | 说明 |
| --- | --- | --- |
| 数值输入 | 省略值，保留必要类型和标签 | 真实的 0 也是值，不自动允许输出 |
| 日期输入 | 省略真实日期；必要时用“期初/期末/交易日”等角色 | 任意平移日期会影响月末、闰年和期间判断 |
| 计算结果 | 省略真实结果与缓存 | 即使上游输入省略，结果仍可能透露数据 |
| 名称和标识 | 使用项目内一致代号 | 标签也要检查，不依赖手机号等正则穷尽敏感信息 |
| 公式里的业务数字 | 参数化 | 参数只带类型和经确认角色，不带范围、尾数或比例近似 |
| 函数语义常量 | 仅按语境白名单保留 | 如 ROUND 的位数、查找模式；不能对所有位置允许 0、1、2 |
| 比较、逻辑及错误类型 | 保留结构 | IF 的真实执行分支不对外提供 |
| 字符串字面量 | 公共技术值按白名单保留；其余代号或参数化 | 例如空字符串、通用提示可配置；客户名称仍要替换 |
| 通配与模糊条件 | 支持专门的模式表达后才可导出 | 直接将 `某公司*` 替换为 `ENTITY_001` 会丢失匹配语义 |
| 单元格与区域地址 | 默认保留匿名文件/表内地址 | 对规模敏感时改为模板级导出，并注明追溯损失 |
| 公式型名称、未知语法 | 默认阻止其内容导出 | 仅输出匿名位置与状态代码 |
| 任意摘要、说明、报错、文件标题 | 同一检查规则 | 没有“日志/报告天然安全”的例外 |

敏感内容检查需要对最终序列化后的每个文件再运行；字符串转义、JSONL 分片、公式摘要不能成为漏出路径。残留扫描不能替代前面的字段白名单与类型边界。

## 4. 逻辑与数据的区别

原公式（虚构）：

```excel
=IF(SUMIFS('示例基金'!H:H,'示例基金'!B:B,"示例客户")>500000,"需关注","")
```

分析表达式：

```text
=IF(SUMIFS(N_MARKET_RANGE,N_ENTITY_RANGE,P_ENTITY)>P_THRESHOLD,"需关注","")
```

`P_ENTITY` 是客户标识条件，`P_THRESHOLD` 是业务阈值，真实值仅在本地。表达式供模型解释，不是重命名后可直接运算的完整 Excel 文件。查找与条件函数输出潜在数据依赖，不能声称知道实际命中行。

敏感值不应默认乘比例、加噪声或保留前三位：这些方式既可能泄露相对关系，又可能改变 IF、排序、阈值、四舍五入和勾稽行为。需要数值验证时，生成独立合成数据或在本地执行检查。

## 5. 导出检查流程

1. 使用安全类型逐字段构造导出对象；禁止对原对象 `__dict__` 整体序列化。
2. 校验所有引用、参数和匿名编号；未解析依赖必须有占位与状态。
3. 通过 JSON Schema 校验，拒绝未定义字段。
4. 对表达式重新解析并检查字面量角色；对标签、说明、参数语义应用允许列表。
5. 在本地使用敏感名称词典、私有路径和已发现业务字面值检查残留；对短数字等有歧义项按语法位置判断，不作盲目全局字符串替换。
6. 检查仅包含明确允许的导出文件；原文件、数据库、对照表、缓存及调试日志不得打包。
7. 展示实际导出预览及缺失范围；任何有疑问的内容保持 blocked，不能用“低风险”自动放行。
8. 检查通过并由用户确认后发布文件；是否提交外部模型由用户另行操作。

若用户选择“仅导出已检查子集”，未知项以 `unknown` 节点表示，结果的 completeness 必须为 `incomplete`。默认全量严格模式存在未知脱敏项即阻止发布。

## 6. 缓存与附属对象

Excel 的公式可能同时存有 `<f>` 和 `<v>`，其中后者可保存计算结果；透视表、数据模型等也可能保存不可见源数据。因此本项目重新构造逻辑包，不复制清空后的工作簿。[微软公式说明](https://learn.microsoft.com/en-us/office/open-xml/spreadsheet/working-with-formulas)、[微软缓存说明](https://support.microsoft.com/en-us/excel/items-that-may-have-cached-data-found)

外部链接可能位于名称、对象、图表等位置，不能只检查单元格字符串。本地读取阶段用结构检测识别相关部件，导出阶段采用允许文件集合。[微软外部链接说明](https://support.microsoft.com/en-us/excel/external-links-found)

## 7. 必须保留的真实性说明

- 脱敏包能够支持公式结构解释，不代表能够复核真实金额。
- 任意“缺失来源”“人工粘贴”“动态引用”“未支持语法”都必须保留。
- 行业通用名称是否允许公开由项目规则决定；本工具不把自动识别当作公开授权。
- 对外 JSON Schema 只能约束结构，不能替代脱敏检查或人工预览。

## 8. 本地持久化与对外内容

真实业务值、原始公式、文本、名称对照和缓存允许保存在用户电脑的独立项目目录，支持本地浏览、复核及后续数值检查。原工作簿保持只读，运行数据库、WAL/SHM、备份和临时索引均按私有数据管理，不进入仓库、在线 CI 或导出包。

普通日志使用匿名编号、固定错误代码和统计；本地诊断原文如需保存，应置于私有项目目录，不并入可分享报告。方案讨论及提交只记录通用设计、经检查的结构特征和从零构造的用例，不记录实际业务值、原始公式、名称或文件标识。

分类不能决定公开资格：文本可能是标题也可能是客户名称，数字可能是金额也可能是技术常量，公式也可能内嵌敏感数据。所有内容仍须经过语义检查、公式常量参数化与独立安全 DTO 导出。
